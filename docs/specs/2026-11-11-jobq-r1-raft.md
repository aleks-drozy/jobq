# jobq R1: Raft core, proven in simulation

Status: built 2026-11-11 on `feat/raft-core`. First of four replication
milestones (R1 Raft core, R2 the queue on Raft, R3 snapshots and AWS, R4
fault injection on real machines).

## What R1 is

A `raft/` package in the root module, standard library only: leader
election, log replication, the commit rule, and persistence of term, vote
and log. Nothing in jobq uses it yet. R1's job is to earn trust in the
algorithm before a queue is put on top of it.

## The shape: a node that does no I/O

A `Node` has no goroutines, no timers and no sockets. Time arrives as
`Tick()`, the network arrives as `Step(msg)`, client writes arrive as
`Propose(data)`, and everything the node wants done comes back from
`Ready()`: messages to send and entries that are now committed.

This is the same idea as the rest of jobq (an injectable clock, a suite
that never sleeps) taken one step further. Because the node is a pure
function of its inputs, a test can drive a whole cluster from one seeded
random source and replay any failure exactly.

The node is not safe for concurrent use. One goroutine owns it, which is
the actor model the queue already uses per topic.

## Decisions

**Persist first, then speak.** `Storage` methods must be durable before
they return, and the node updates its in-memory state only after they do.
A granted vote or an acknowledged append is therefore always on disk
before the message that promises it exists. A storage error is sticky:
the node stops, the same fail-closed rule the WAL follows.

**Every new leader appends a no-op.** A leader may only count replicas for
entries of its own term (the Figure 8 rule). Without a no-op, a leader
with no fresh proposals could never commit what it inherited.

**A follower's commit index never runs past what the leader just
verified.** `min(leaderCommit, prevIndex + len(entries))`, not
`min(leaderCommit, lastIndex)`: a follower can hold a stale suffix the
current message said nothing about.

**Rejections carry a hint and echo what they reject.** The hint lets the
leader skip a short follower's missing range in one step. The echo lets
the leader ignore a rejection that arrives late, which would otherwise
walk `next` backwards a second time.

**Messages copy their entries.** A follower truncating its log must not
rewrite a message still in flight. `Propose` copies the caller's buffer
for the same reason the queue copies payloads.

**Fixed membership, no pre-vote, no leases.** A partitioned node inflates
its term and disrupts the cluster once when it returns. That costs an
election, never safety. Pre-vote is on the later list.

## The simulator

`sim_test.go` runs 3 and 5 node clusters for 400 steps of chaos, all of it
decided by one seed:

- messages dropped (10%), duplicated (5%), delayed up to 3 steps, and so
  reordered
- nodes crashed and restarted from their storage, any number at once
- two-way partitions at a random split, and one-way cuts of single links
- node clocks that skip ticks
- clients proposing to every node that believes it leads, deposed leaders
  included

After every step it checks, against a record of everything any node has
ever claimed:

| Property | Check |
|---|---|
| Election safety | at most one node ever leads a given term |
| Leader completeness | a new leader holds every entry committed so far |
| State machine safety | no two nodes apply different entries at one index |
| Log matching | two logs that agree on a term at an index agree on everything before it (every 25 steps, crashed nodes' disks included) |
| Apply order | each node applies indexes in order with no gaps |

Then the chaos stops, every node restarts, the network heals, and the
cluster must elect a leader, commit a fresh proposal and bring every node
to an identical applied log. A run cannot pass by doing nothing.

### Results

10,000 seeds, under the race detector, zero violations. Across those runs:
34,185 leaders elected, 875,736 entries committed of 889,289 proposed,
47,957 crashes, 48,118 partitions, 3.0 million messages dropped and
762,247 duplicated out of 16.2 million delivered. 9,711 of the 10,000 runs
changed leader at least once. The suite fails if those fault counts ever
fall to a level where the simulator is no longer exercising them.

`go test ./raft` runs 1,000 seeds by default; CI runs all 10,000.

    go test ./raft -run 'TestSimulation$' -raft.sims=10000
    go test ./raft -run 'TestSimulation$' -raft.seed=12345 -v   # replay with a trace

### Are the checks real?

`TestSimulationCatchesBrokenRaft` breaks one rule at a time inside the
node and requires the simulator to notice and name the property:

| Bug planted | Caught as | Seed |
|---|---|---|
| Vote twice in one term | election safety | 1 |
| Vote for a candidate with a stale log | leader completeness | 3 |
| Commit an inherited entry by counting replicas (Figure 8) | leader completeness | 3453 |

The third is the honest one. Under the default fault mix, 3,000 seeds ran
clean with the bug in place. It needs a leader to die between committing
an inherited entry and replicating anything of its own, then lose the next
election to a node that never saw the entry. It took one entry per
message, 25% message loss and five times the crash rate to hit that window,
at seed 3453. A random simulator finds shallow bugs fast and deep ones
slowly, and 10,000 clean runs are evidence, not proof. The Figure 8 rule
also has its own deterministic unit test for that reason.

## What R1 does not do

- No real network or disk: `MemoryStorage` only. The simulator's crash
  model is "everything persisted survives", which is true only because
  writes are synchronous. R2 puts the log on the existing WAL, where a
  torn tail is possible and must be shown harmless.
- No snapshots or log compaction (R3). The log grows forever, and a
  restarted node is handed its committed entries again from index 1.
- No membership changes, no pre-vote, no linearizable reads.
- No pipelining: a leader resends from `next` until acknowledged. Correct,
  not yet fast.
- Nothing has been measured. There are no latency or throughput numbers
  for this package and none are claimed.
